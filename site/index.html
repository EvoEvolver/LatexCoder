The writing surface

Built for the paper, not the browser tab.

Files, source, PDF, comments, logs, and version history stay close enough to move through without losing context.

01

Source and PDF, side by side

Resize the workspace, navigate included files, and move between source and the compiled paper with SyncTeX.

  • Project-wide file tree and tabs
  • Bidirectional source/PDF navigation
  • First-fatal-error Log workflow
02

Review data agents can actually read

Comments, replies, and suggestions are stored as macros in the source instead of disappearing into an opaque review database.

  • Inline comments and threaded replies
  • Project-wide Review view
  • Character-level blame and Git provenance
03

See who wrote every range

Turn on Blame to inspect continuous authorship directly in the editor, then follow a range back to the Git checkpoint that introduced it.

  • Character-level attribution
  • Human, agent, and Git identity hints
  • Linked version history and word-level diffs
04

Understand before you jump

Hover over citations, formulas, references, and graphics to inspect what they mean without leaving the sentence you are writing.

  • Citation metadata with authors and title
  • KaTeX previews with custom macro expansion
  • Referenced image and PDF previews
05

Git without a second source of truth

Every project is a real repository. Live Yjs state stays on main, pulls checkpoint current browser edits, and incoming work is merged before import.

  • Personal clone and push URLs
  • Recoverable conflict branches
  • Checked full-file editing API for agents

One paper, three interfaces

No export ritual between collaborators.

Human

Edit live

Use the full editor, PDF, review, history, blame, and project navigation.

Agent

Patch safely

Download a file, return a checked replacement, and fail cleanly if the base changed.

Git

Clone normally

Pull live checkpoints and push commits back through the same project history.
